## N-MNIST 資料集

用真實事件相機資料集,不自建 latency encoding——資料本身就是 (x, y, polarity, t),
事件數不固定,貼近「處理真實非同步事件流」的目標。

**格式**(官方規格,70000 檔實測驗證):34×34、2 channel(ON / OFF)、
40-bit AER(X / Y 各 8bit、polarity 1bit、timestamp 23bit,單位微秒)。
事件數分布:min 652、max 8183、mean 4176.5、p99 6727。

| 項目 | 決定 |
|---|---|
| 時間量化 | `t_微秒 // 1000`(floor,對齊 FPGA 慣例) |
| 同毫秒 tie-break | 檔案原始順序 |
| stabilize.m 運動補償 | 不做 |
| polarity → channel | c=0(OFF)、c=1(ON) |
| 事件數截斷 / padding 長度 | **2000**(每個樣本取前 2000 筆,超過截斷、不足 pad)。原本 8183(全資料集最大值、無截斷)在 12GB VRAM 上連 batch=2 都 OOM;conv 佇列只放感受野內的事件(`build_conv_structure`)是根本解法,2000 是過渡值 |
| Train / Val 切分 | Train 60000 筆切 10% 當 val(簡單隨機) |
| 第一次訓練規模 | train 1000 / val 200 / test 200 |
| 檔案 | `data/src/nmnist.py`(+ `data/tests/test_nmnist.py`) |

## conv 網路架構

只用 conv + FC,不用 pooling:

$$\text{conv1} \to \text{conv2} \to \text{flatten} \to \text{FC(輸出層)}$$

| 層 | 規格 |
|---|---|
| conv1 | $IC{=}2, OC{=}8, K{=}3, S{=}2, P{=}1$($34\times34 \to 17\times17$) |
| conv2 | $IC{=}8, OC{=}16, K{=}3, S{=}2, P{=}1$($17\times17 \to 9\times9$) |
| FC(輸出層) | flatten 後 $1296 \to 10$ |

conv1 / conv2 是會 fire 的隱藏層;FC 輸出層 $v_{th} = 10^9$,不 fire,純積分器,
10 個 $v_{final}$ 當 logits 送 `softmax_cross_entropy`。

**超參數**:$\tau = 16.0$、$\alpha = 2.0$(surrogate 銳度)、$v_{th,\text{hidden}} = 1.0$。

**`init_k`**(權重初始化縮放,$\text{limit} = \text{init\_k}/\sqrt{\text{fan\_in}}$):
三層全部 **`5.0`**,committed 值,不校準。舊的「firing-rate 目標帶掃描」準則
(選出 conv1 = 8.0 / conv2 = 64.0)訓練較差,已廢棄——完整推導 + V1–V6 實測見
[`math/初始權重尺度推導.md`](math/初始權重尺度推導.md)。

**容量**(`max_queue_len` / `max_out_spikes` / `max_extra_steps`):起始猜測 + 訓練中偵測出界就放大
(`salt_core/capacity.py` 的 `GrowthPolicy`、`grown_to_fit`),不靜態精算;config 給的是起始值。
`max_queue_len` 只長不縮;`max_out_spikes`、`max_extra_steps` 會縮,見下一節表格最後兩列。
`max_queue_len` 的需求是這批最擠的位置的真事件數 + 1(catch-up 欄)。

## 掃描步數旋鈕 `max_extra_steps`

浮點掃描的步數 = 基本步數 $\lceil L/\text{chunk\_size}\rceil$ + `max_extra_steps`。基本步數是
不 fire 時每步吃滿一個 chunk 的步數,編譯時從佇列長度 $L$ 現算;旋鈕只記因為 fire 要多跑的步數。
完整證明見 [`math/掃描步數上界推導.md`](math/掃描步數上界推導.md)。

2026-09-28(架構審查階段 7)從「總步數 `max_steps`」改成這個定義:FC 的 $L$ 是上一層的輸出容量,
存總步數的話上一層放大時會過時,多一次退回、重編譯;conv 一起改,兩種層同一個定義。

| 決定 | 內容 |
|---|---|
| 上界公式 | $m^{*}=\min(m,\lfloor S/v_{th}\rfloor)$(數正負號 vs 用權重大小算能量預算,取更緊的),$T\le m^{*}+\lceil(L-m^{*})/\text{chunk\_size}\rceil$ |
| 需求 | $T$ 的上界減基本步數,對所有神經元取 `max`,批次縮減也用 `max`。不 fire(例如 `v_th=1e9`)或 `chunk_size=1` 時是 0 |
| 沒填時(conv) | 一定夠的值 $L-\lceil L/\text{chunk\_size}\rceil$,總步數等於 `max_queue_len`(每步至少吃一筆)。只服務沒經過 `train()` 動態放大迴圈的呼叫端;訓練 config 給小的起始猜測 |
| `max_extra_steps_grow_factor`(預設 `1.5`) | 長大跟縮小共用同一個倍率:目標值都算 `ceil(觀察值 * factor)`,不是精確值。真實需求沒變時,長大存下來的值、縮小重算的值必然相等,天然防震盪 |
| `max_extra_steps_shrink_threshold`(預設 `0.5`) | 縮小要不要真的觸發的效率門檻:縮小候選值要掉到現值的這個比例以下才值得付一次重編譯代價。不影響防震盪(那是倍率共用的效果) |
| 長大(安全網) | 每個 batch 檢查(跟 `max_queue_len`/`max_out_spikes` 出界同一條路):需求超過現值 → 補到 `ceil(需求 * 倍率)`、退回、重編譯。**必須立刻處理**,拖到下次重估會讓 forward 結果算錯,不是變慢而已。跟 `max_queue_len` 同一批也出界時,直接設成一定夠的值 $L_{新}-\lceil L_{新}/\text{chunk\_size}\rceil$(那批的需求是在裝不下的佇列上算的,不可信) |
| 沒填時(FC) | 0:不 fire 時剛好夠。FC 的 $L$ 是上一層的輸出容量,建構時不知道,算不出一定夠的值;會 fire 時不夠由 `fits` 偵測、放大 |
| 換 `chunk_size`(例如 replay 換成 1) | conv 設成一定夠的值;FC 不改(`chunk_size=1` 時需求一定是 0,其他值由 `fits` 偵測) |
| 縮小(選擇性優化) | **2026-09-12 改版**:拔掉原本「epoch 開始前用固定探測批重估」的設計(會跟長大安全網互相蓋掉、無限循環,見 [`math/掃描步數上界推導.md`](math/掃描步數上界推導.md)「為什麼不能每個 batch 都套用」)。改成:每 `N` 個**成功跑完的** epoch(config 旋鈕 `train.shrink_check_every`,**預設 1**),用這個 epoch 裡**所有真實 batch**的需求最大值算候選值,掉到門檻以下就縮、觸發重編譯。**不需要**退 checkpoint(用的是已經確定沒問題的當下權重,不是修正錯誤) |
| `max_out_spikes` 縮小(2026-09-12 新增) | 比照上面縮小整套規則(同一個 `train.shrink_check_every` 頻率、同樣不用退 checkpoint),**差別只在觀察值來源**:吃真實的輸出 spike 數(跟長大訊號同一個量),不是任何理論上界。`out_shrink_threshold`(預設 `0.5`),長大/縮小公式共用 `out_grow_factor`。曾經嘗試過讓 `max_out_spikes` 改用 $m^*$ 加總(`Σm*_i`)當主動長大/縮小訊號,完整測試後發現在這個專案的實際權重規模下鬆到把出界測試矩陣打壞,已撤回——理由跟「步數上界為什麼不能拔掉 `m*`」的結構性差異,見 [`問題紀錄.md`](問題紀錄.md)「洞見:掃描步數上界不能拔掉 `m*`,`max_out_spikes` 不能再用它——兩者不是同一種問題」 |

## FPGA 部署:權重量化

目標硬體 CSNN-FPGA 的位元寬度候選最大 8 bits,能再小更好。這節只處理權重;膜電位量化見
[`math/膜電位量化推導.md`](math/膜電位量化推導.md),剪枝評估後暫不做(見 [`TODO.md`](TODO.md)「開放題」)。
最後用哪組參數還沒定案,見 [`TODO.md`](TODO.md)「量化參數還沒定案」。完整推導見
[`math/權重量化推導.md`](math/權重量化推導.md)。

| 決定 | 內容 | 狀態 |
|---|---|---|
| 量化方法 | 線性/均勻對稱量化,無 zero-point,整數範圍 $\{-(2^{b-1}-1), \dots, 2^{b-1}-1\}$ | 已定 |
| Clip threshold 選法 | 對經驗分布網格搜尋 MSE 最小(候選取 $\lvert w \rvert$ 的多個 percentile),不套用 ACIQ 之類假設 Gaussian/Laplacian 分布的解析解——本專案權重分布是否符合任一參數分布還沒驗證 | 已定 |
| Per-tensor / per-channel | 待對 checkpoint(`experiments/scale_10k_20260919_050446/train/params.npz`,val_accuracy 0.9275)算 per-channel 權重量級分布後決定 | 待驗證 |
| Bit width | 上限 8 bits,實際值待 PTQ(post-training,不重訓)準確率掃描決定 | 待驗證 |
| 對稱性假設 | 假設訓練後權重分布仍近似零均值對稱(來自 `uniform_init` + `weight_decay` 不引入偏移的推論),待 histogram 驗證,不對稱則需退回 affine quantization | 待驗證 |
| 程式碼位置 | 核心量化函式(`fake_quantize_tensor`/`quantization_error`/`quantize_params`)放 `salt_core/quant/ptq.py`,純函式、可測試、不碰 data/example,比照 `salt_core/dormant.py` 的判準;一次性視覺化/統計探索(histogram、PTQ 掃描曲線)放 `example/notebooks/`,不留可測試 `.py`,比照 `plot_metrics.ipynb`/`replay_animation.ipynb` 前例 | 已定 |
| QAT(若 PTQ 掉太多才做) | straight-through estimator(`jax.custom_vjp`,clip 範圍內恆等、範圍外歸零),跟 `salt_core/float/surrogate.py` 處理 spike 不可微同一套路 | 已定,實作延後 |

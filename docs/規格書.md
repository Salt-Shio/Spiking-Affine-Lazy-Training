## N-MNIST 資料集

用真實事件相機資料集,不自建 latency encoding——資料本身就是 (x, y, polarity, t),
事件數不固定,貼近「處理真實非同步事件流」的目標。

**格式**(官方規格,70000 檔實測驗證):34×34、2 channel(ON / OFF)、
40-bit AER(X / Y 各 8bit、polarity 1bit、timestamp 23bit,單位微秒)。
事件數分布:min 652、max 8183、mean 4176.5、p99 6727。

| 項目 | 決定 |
|---|---|
| 時間量化 | `t_微秒 // 1000`(floor,對齊 FPGA 慣例) |
| 同毫秒 tie-break | 檔案原始順序 |
| stabilize.m 運動補償 | 不做 |
| polarity → channel | c=0(OFF)、c=1(ON) |
| 事件數截斷 / padding 長度 | **2000**(每個樣本取前 2000 筆,超過截斷、不足 pad)。原本 8183(全資料集最大值、無截斷)在 12GB VRAM 上連 batch=2 都 OOM;壓縮版佇列(`build_conv_queue_compressed`)是根本解法,2000 是過渡值 |
| Train / Val 切分 | Train 60000 筆切 10% 當 val(簡單隨機) |
| 第一次訓練規模 | train 1000 / val 200 / test 200 |
| 檔案 | `data/src/nmnist.py`(+ `data/tests/test_nmnist.py`) |

## conv 網路架構

只用 conv + FC,不用 pooling:

$$\text{conv1} \to \text{conv2} \to \text{flatten} \to \text{FC(輸出層)}$$

| 層 | 規格 |
|---|---|
| conv1 | $IC{=}2, OC{=}8, K{=}3, S{=}2, P{=}1$($34\times34 \to 17\times17$) |
| conv2 | $IC{=}8, OC{=}16, K{=}3, S{=}2, P{=}1$($17\times17 \to 9\times9$) |
| FC(輸出層) | flatten 後 $1296 \to 10$ |

conv1 / conv2 是會 fire 的隱藏層;FC 輸出層 $v_{th} = 10^9$,不 fire,純積分器,
10 個 $v_{final}$ 當 logits 送 `softmax_cross_entropy`。

**超參數**:$\tau = 16.0$、$\alpha = 2.0$(surrogate 銳度)、$v_{th,\text{hidden}} = 1.0$。

**`init_k`**(權重初始化縮放,$\text{limit} = \text{init\_k}/\sqrt{\text{fan\_in}}$):
三層全部 **`5.0`**,committed 值,不校準。舊的「firing-rate 目標帶掃描」準則
(選出 conv1 = 8.0 / conv2 = 64.0)訓練較差,已廢棄——完整推導 + V1–V6 實測見
[`math/初始權重尺度推導.md`](math/初始權重尺度推導.md)。

**壓縮佇列容量**(`max_queue_len` / `max_out_spikes`):起始猜測 + 訓練中偵測出界就放大
(`ConvLayer.grown_to_fit`),不靜態精算;config 給的是起始值。`max_queue_len` 目前只長
不縮;`max_out_spikes` 2026-09-12 補上縮小路徑,見下一節表格最後一列。

## conv 層 `max_steps`(掃描步數上界)

`max_steps` 從 `max_queue_len` 脫鉤,不再無腦等於 `max_queue_len`。完整證明見
[`math/掃描步數上界推導.md`](math/掃描步數上界推導.md);背景見
[`TODO.md`](TODO.md)「`max_steps` 與 `chunk_size` 脫鉤」。

| 決定 | 內容 |
|---|---|
| 上界公式 | $m^{*}=\min(m,\lfloor S/v_{th}\rfloor)$(數正負號 vs 用權重大小算能量預算,取更緊的),$T\le m^{*}+\lceil(L-m^{*})/\text{chunk\_size}\rceil$ |
| 新欄位:`LayerDiag.min_steps_needed` | 在 `ConvLayer.forward` 算(跟 `max_real_queue` 同一個位置,原料是 `cq.maps.b`),對所有神經元取 `max`,批次縮減也用 `max`(跟 `max_real_queue`/`n_out_spikes` 同一套規則) |
| 新欄位:`ConvLayer.max_steps` | 獨立於 `max_queue_len` 的靜態欄位(不再是 `self.max_queue_len` 直接當 `max_steps` 用) |
| 起始值 | config 給小的起始猜測(跟 `max_queue_len`/`max_out_spikes` 同一種用法),不靠 `ConvLayer.__post_init__` 的 `None -> self.max_queue_len` fallback 打底(那個 fallback 只服務沒經過 `train()` 動態放大迴圈的呼叫端) |
| 新欄位:`ConvLayer.max_steps_grow_factor`(預設 `1.5`) | 長大跟縮小共用同一個倍率:目標值都算 `ceil(觀察值 * factor)`,不是精確值。真實需求沒變時,長大存下來的值、縮小重算的值必然相等,天然防震盪 |
| 新欄位:`ConvLayer.max_steps_shrink_threshold`(預設 `0.5`) | 縮小要不要真的觸發的效率門檻:縮小候選值要掉到現在 `max_steps` 的這個比例以下才值得付一次重編譯代價。不影響防震盪(那是 `max_steps_grow_factor` 共用的效果) |
| 長大(安全網) | 每個 batch 檢查(跟 `max_queue_len`/`max_out_spikes` 出界同一條路):`min_steps_needed` 超過現在 `max_steps` → 補到 `ceil(min_steps_needed * max_steps_grow_factor)`、退回 checkpoint、重編譯。**必須立刻處理**,拖到下次重估會讓 forward 結果算錯,不是變慢而已。跟 `max_queue_len` 同一批也出界時,直接補到新 `max_queue_len`(那批的 `min_steps_needed` 是舊佇列算的,不可信) |
| 縮小(選擇性優化) | **2026-09-12 改版**:拔掉原本「epoch 開始前用固定探測批重估」的設計(會跟長大安全網互相蓋掉、無限循環,見 [`math/掃描步數上界推導.md`](math/掃描步數上界推導.md) 第 6 節)。改成:每 `N` 個**成功跑完的** epoch(config 旋鈕 `train.max_steps_reestimate_every`,**預設 1**),用這個 epoch 裡**所有真實 batch**的 `min_steps_needed` 觀察最大值算候選值,掉到門檻以下就縮、觸發重編譯。**不需要**退 checkpoint(用的是已經確定沒問題的當下權重,不是修正錯誤) |
| `max_out_spikes` 縮小(2026-09-12 新增) | 比照上面 `max_steps` 縮小整套規則(同一個 `train.max_steps_reestimate_every` 頻率、同樣不用退 checkpoint),**差別只在觀察值來源**:吃 `LayerDiag.n_out_spikes`(真實觀察值,跟長大訊號同一個量),不是任何理論上界。新欄位 `ConvLayer.out_shrink_threshold`(預設 `0.5`)對應 `max_steps_shrink_threshold`,長大/縮小公式共用既有的 `out_grow_factor`。曾經嘗試過讓 `max_out_spikes` 改用 `spike_step_upper_bound` 內部的 `m*` 加總(`Σm*_i`)當主動長大/縮小訊號,完整測試後發現在這個專案的實際權重規模下鬆到把出界測試矩陣打壞,已撤回——理由跟「`max_steps` 為什麼不能拔掉 `m*`」的結構性差異,見 [`問題紀錄.md`](問題紀錄.md) 第十四節 |

## FPGA 部署:權重量化

目標硬體 CSNN-FPGA 的位元寬度候選最大 8 bits,能再小更好。這是「權重量化/
剪枝/膜電位量化三部曲」(見 [`TODO.md`](TODO.md)「待處理」第一條)的第 1 步,
只處理權重;剪枝、膜電位量化定案後個別回來補這節。完整推導見
[`math/權重量化推導.md`](math/權重量化推導.md)。

| 決定 | 內容 | 狀態 |
|---|---|---|
| 量化方法 | 線性/均勻對稱量化,無 zero-point,整數範圍 $\{-(2^{b-1}-1), \dots, 2^{b-1}-1\}$ | 已定 |
| Clip threshold 選法 | 對經驗分布網格搜尋 MSE 最小(候選取 $\lvert w \rvert$ 的多個 percentile),不套用 ACIQ 之類假設 Gaussian/Laplacian 分布的解析解——本專案權重分布是否符合任一參數分布還沒驗證 | 已定 |
| Per-tensor / per-channel | 待對 checkpoint(`experiments/conv_compressed_compressed_scale_10k_20260919_050446/train/params.npz`,val_accuracy 0.9275)算 per-channel 權重量級分布後決定 | 待驗證 |
| Bit width | 上限 8 bits,實際值待 PTQ(post-training,不重訓)準確率掃描決定 | 待驗證 |
| 對稱性假設 | 假設訓練後權重分布仍近似零均值對稱(來自 `uniform_init` + `weight_decay` 不引入偏移的推論),待 histogram 驗證,不對稱則需退回 affine quantization | 待驗證 |
| 程式碼位置 | 核心量化函式(`fake_quantize_tensor`/`quantization_error`/`quantize_params`)放 `salt_core/quant/ptq.py`,純函式、可測試、不碰 data/example,比照 `salt_core/dormant.py` 的判準;一次性視覺化/統計探索(histogram、PTQ 掃描曲線)放 `example/notebooks/`,不留可測試 `.py`,比照 `plot_metrics.ipynb`/`replay_animation.ipynb` 前例 | 已定 |
| QAT(若 PTQ 掉太多才做) | straight-through estimator(`jax.custom_vjp`,clip 範圍內恆等、範圍外歸零),跟 `salt_core/float/surrogate.py` 處理 spike 不可微同一套路 | 已定,實作延後 |

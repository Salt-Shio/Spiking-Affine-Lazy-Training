## 目標

- `train()` 的資料從外面傳進去;放大、縮小事件結構化記錄。
- 出界測試用合成資料精準命中邊界,不解析印出來的訊息。

  - 訓練本身另外做一次性前後比對(6.1 第 6 項)。

## 合成測試測的是什麼

主題是**訓練迴圈遇到容量出界時,有沒有正確地退回去重來**:

1. 丟掉出界的 batch,連同這個 epoch 已經套用的更新。
2. 退回正確的起點:沒存過 checkpoint 就重新初始化,存過就讀最近的 checkpoint。
3. 用放大後的容量重編譯續練。

驗證方式:最後的權重要跟「一開始就給夠容量、從沒出界」的訓練一致。

forward 算得對不對由 `salt_core/tests` 測;放大公式由 `test_capacity_fit.py` 測。

### 多層出界

- 網路只有一個 `fits`:每個有容量的層都放得下才是 True。
- False 時 `grown_to_fit` 逐層看需求,每層各自放大放不下的旋鈕,一次重來就把所有出界的層一起放大。
- conv1 出界時,conv2 的需求是在被截掉的輸入上算的,不可信;放大後可能再重來一次,
  下一次跑到時迴圈會再偵測到,不需要特別處理。
- 現有的 `grown_to_fit` 測試只有一層 conv,「只有第二層出界」「兩層同時出界」沒有測試,
  這個階段補上(6.2 第 8、12 項)。

## 6.2 出界測試改用合成資料(第 26 條)

7. 合成資料(`_train_runs.py`):
   - 網路:輸入 2×8×8、兩層 conv + FC,每筆最多 32 筆事件。
   - 第 i 筆樣本的 n_i 筆事件放同一個像素,n_i 各不相同。conv1 的佇列需求就是 n_i,跟權重無關
     (實測:5、9、17、33 筆 → 需求 5、9、17、33)。
   - 不針對的旋鈕給理論上限,保證不出界:conv1 輸出 spike 數最多是事件數 × 4 × oc;
     conv2 的佇列最多是 conv1 輸出 spike 數,輸出 spike 數最多是它 × 4 × oc。
   - 縮小關掉(`max_steps_reestimate_every: 0`),只有測試指定的出界會發生。
8. conv2 的需求會隨權重變,但**第一個 batch 還沒更新**,權重是初始值:測試先用初始權重量出
   conv2 在第一個 batch 的需求,容量設得比它小,就能精準在 (epoch 0, batch 0) 出界。
9. 邊界的命中方式:用 `epoch_permutation` 找一顆 seed,讓需求最大的樣本在 epoch 0 剛好是湊不滿
   batch、被丟掉的那筆,epoch 1 才排進來。容量只照各 batch 的需求設,不用校準數字。
10. 共用一次參考訓練:合成資料、容量給足、3 epoch、每個 epoch 存權重快照。
11. 出界測試(斷言事件,不解析訊息):
    - reinit:第一次出界在 (0, 0),`resumed_from_epoch` 是 None;最終權重跟參考訓練容差內一致。
    - midepoch:第一次出界在 (0, 1),同上。
    - resume(同行程):出界在 epoch 1、`resumed_from_epoch` 是 0;`metrics.csv` 的 epoch 是
      0、1、2 各一次;容量欄位 epoch 0 記舊值、之後記新值;權重跟參考訓練一致。
    - 最後一個 epoch:同 resume 的設定但 2 epoch,出界在 epoch 1;權重跟參考訓練的 `epoch_001` 快照比。
    - 只有 conv2 出界:(0, 0) 出界,事件只有 conv2 的旋鈕;權重跟參考訓練一致。
    - 兩層同時出界:(0, 0) 出界,同一個事件裡兩層都有;權重跟參考訓練一致。
    - 連續出界:conv1 容量 1、倍率 1.01,預期次數從已知的 n_i 跟 shuffle 順序算出來,斷言剛好相等。
    - `max_out_spikes` 出界:用初始權重量第一個 batch 的需求,容量設得比它小,(0, 0) 出界;
      權重跟參考訓練一致。
    - optimizer 四個選項全開改用合成資料。
    - 原本「conv1 佇列出界會放大不會 raise」併進 reinit。
    - 新增:合成樣本的 conv1 佇列需求等於事件數(確認構造成立)。
12. 單元測試(`test_capacity_fit.py`,兩層 conv、手寫需求):
    - conv1 沒出界、conv2 出界:只有 conv2 放大,conv1 是原本的物件。
    - 兩層都出界:一次呼叫兩層都放大。
13. 拿掉 `_parse_overflows`、`run_capture`、檔頭的校準說明。真實資料的 `reference_run` 留給

## 決定(2026-09-28)

| 決定 | 結果 |
|---|---|
| 續練要還原的東西存哪 | 全部進 checkpoint,原子寫入 |
| 合成網路幾層 conv | 兩層。conv1 的需求只看輸入,用來精準定位;conv2 只在第一個 batch 用初始權重量需求 |
| 分幾步 | 6.1、6.2、6.3 分開,6.1 留舊測試當安全網 |

理由:

- 全部進 checkpoint:只有一個檔、原子寫入,不會有「best 已存、checkpoint 還沒存」這種對不上的中間狀態。
- 兩層 conv:只有一層時「只有 conv2 出界」「兩層同時出界」測不到;第一個 batch 的權重是初始值,
  conv2 的需求可以先量再設容量,不用校準數字。

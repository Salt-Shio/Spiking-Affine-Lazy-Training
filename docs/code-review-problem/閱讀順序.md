# 程式碼閱讀順序

架構審查重構(階段 0–8)做完後，從頭重新讀懂整個專案用的順序。自己讀，卡住再問。

## 怎麼讀

- 分成幾個主題，每個主題從一個入口開始，**由上往下**沿著呼叫走。
- 每個主題先看「呼叫樹」,知道整條路長什麼樣，再照樹一層一層讀。
- 讀一個函式時，只先搞懂它的輸入跟輸出；它底下呼叫的函式先當黑盒，照樹往下讀到才打開。
- 「深入閱讀」是演算法內部，選讀。不讀也不影響理解主題的主線。
- 主題之間會互相接：樹上寫「= 主題 N」的節點，就是另一個主題的入口。
- 推導文件只在卡在「為什麼這樣算」的時候查，不用先讀完。
- 讀完用「讀完要能回答」自我檢查，答不出來的就是要問的地方。
- 提問時附檔案跟行號，例如 `float/affine.py` 第 147 行。
- 讀的過程找到的問題記在 `閱讀發現.md`,讀完全部再一起處理。

## 主題 1:一筆樣本怎麼變成分數(浮點 forward)

**入口**:`salt_core/network.py` 的 `Network.apply`

**呼叫樹**

```
Network.apply(weights, raw)                          salt_core/network.py
│   InputEvents → NetworkOutput
├─ Network.input_stream(raw)                         salt_core/network.py
│      InputEvents → EventStream(第一層的輸入)
└─ run_network(layers, weights, stream)              salt_core/network.py
   │   一層一層跑，每層的輸出流接給下一層
   ├─ ConvLayer.forward(w, stream)                   salt_core/layers/conv.py
   │  ├─ build_structure                             EventStream → ConvQueueStructure
   │  │  └─ build_conv_structure                     salt_core/connectivity/conv.py
   │  ├─ FloatBackend.scan                           salt_core/float/backend.py
   │  │  ├─ layer.float_values → conv_float_values   ConvQueueStructure + 權重 → AffineMap
   │  │  ├─ run_layer                                salt_core/float/scan.py
   │  │  │                                           AffineMap → FloatLayerResult
   │  │  └─ extra_steps_upper_bound                  salt_core/float/affine.py(容量用，主題 3)
   │  ├─ extract_output_events_conv                  salt_core/stream.py
   │  │                                              FloatLayerResult → EventStream
   │  └─ _layer_diag                                 salt_core/layers/base.py → LayerDiag
   ├─ FCLayer.forward                                salt_core/layers/fc.py
   │      同上，換成 FC 版:build_fc_structure、fc_float_values、extract_output_events_fc
   └─ 每層 capacity.fits(diag) 合成 fits             salt_core/capacity.py(主題 3)

呼叫端拿 NetworkOutput.last 再解碼：
MembraneRegressionDecoder.decode(result)             salt_core/decoder.py
    FloatLayerResult → scores
```

**讀的順序**

1. `network.py`:`InputEvents`、`Network`、`input_stream`、`run_network`、`NetworkOutput`。
2. `layers/conv.py` 的 `forward`:一層的骨架，四段(建結構、掃描、抽輸出流、診斷)。
3. `connectivity/conv.py` 的 `build_conv_structure`、`conv_float_values`:只看輸入輸出。
4. `float/backend.py` 的 `scan`,接著 `float/scan.py` 的 `run_layer`:只看輸入輸出。
5. `stream.py` 的 `extract_output_events_conv`、`EventStream`。
6. `layers/fc.py`:跟 conv 對照，只看不同的地方。
7. `decoder.py`:三種解碼器各讀結果的哪個欄位。

## 主題 7:資料怎麼變成網路的輸入、config 怎麼組成網路

兩條線互相獨立，可以分開讀。先讀 A:B 的 `input_shape` 允許任意維度，前提是 A 的入口不綁圖片。

### A:資料 → 網路的輸入

**入口**:`example/utils.py` 的 `split_input_events`

**呼叫樹**

```
split_input_events(split, network.input_shape)       example/utils.py
└─ grid_input_events(t, x, y, c, n, grid_shape)      example/utils.py
   │   (c, y, x) → row-major 攤平編號，座標越界時 raise
   └─ InputEvents.checked                            salt_core/network.py
         檢查時間，包成 InputEvents(時間、source_idx、真事件數)
Network.input_stream(raw)                            salt_core/network.py
│   source_idx 照抄成 event_source_idx,event_gain 補 1
└─ 第一層是 conv 時:ConvLayer.build_structure       salt_core/layers/conv.py
   └─ unravel_conv_source                            salt_core/connectivity/conv.py
         攤平編號 → (x, y, c),跟 grid_input_events 互為逆運算
```

例:輸入形狀 (2, 34, 34),事件 (c=1, y=5, x=7) 攤平成 1 * 1156 + 5 * 34 + 7 = 1333;conv1 收到 1333,反解回 (x=7, y=5, c=1)。

**讀的順序**(由下往上：先看規則從哪來，再看誰照著用)

1. `connectivity/conv.py` 的 `unravel_conv_source`:conv 層怎麼反解來源編號。攤平規則由這裡決定。
2. `network.py` 的 `InputEvents`、`checked`:欄位只有時間、`source_idx`、真事件數。
3. `network.py` 的 `Network.__post_init__`、`input_stream`:`input_shape` 不限維度，入口不做攤平。
4. `example/utils.py` 的 `grid_input_events`、`split_input_events`:圖片座標在資料端攤平。

**測試**:`example/tests/test_grid_input_events.py`、`salt_core/tests/test_network.py`

**讀完要能回答**

- 攤平規則為什麼是 c*H*W + y*W + x,不能自己另訂一條？
- 輸入是 700 個 channel 的音訊事件時,`input_shape` 怎麼設?`source_idx` 放什麼？
- 為什麼不讓呼叫端直接傳 `EventStream`?(`問題紀錄.md`「決策：網路入口吃攤平編號，不知道輸入是不是圖片」)

### B:config → 網路

**入口**:`example/models/conv_net.py` 的 `build_network`

**呼叫樹**

```
build_network(model_cfg)                             example/models/conv_net.py
├─ _layer_groups(model_cfg)                          每層合併過 layer_defaults 的四組
│  └─ _merged_groups(defaults, entry)                同一組的同名 key 層優先，轉型，檢查 key
├─ _layer_spec(entry, groups)                        幾何 + neuron/training/capacity → 層描述
│  └─ conv(...) / fc(...)                            salt_core/layers/conv.py、fc.py
└─ Network.build(input_shape, specs)                 salt_core/network.py
   └─ 每層 spec.build(前一層的輸出形狀, 名字)
      ├─ ConvSpec.build → ConvLayer                  補 ic、h_in、w_in;幾何退化在 ConvLayer 擋
      └─ FCSpec.build → FCLayer                      補 n_in = 形狀的元素總數
build_growth_policies(model_cfg, layers)             example/models/conv_net.py
└─ _layer_groups 的 growth 組 → GrowthPolicy
```

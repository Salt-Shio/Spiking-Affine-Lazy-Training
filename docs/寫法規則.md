# 程式碼寫法規則

docstring 跟註解的寫法。新寫或重寫的程式碼都照這份。

## docstring

- 只回答三件事:
  - 做什麼:一句話。
  - 參數跟回傳:形狀、單位、限制。
  - 什麼情況會 raise。
- 超過大約 10 行,代表那些內容屬於 `docs/`,不屬於程式碼。

## 註解

- 只寫「程式碼本身看不出來的原因」,一到兩行。

## 不寫進程式碼的東西

| 內容 | 放哪 |
|---|---|
| 推導 | `docs/math/` |
| 決策、否決過的做法 | `docs/問題紀錄.md` |
| 歷史、除錯經過 | git |

## 格式

- 不用 markdown:不用反引號、粗體、LaTeX。
- 公式寫純文字,例如 a = (1 - 1/tau) ** dt。

## 設計理由只寫一次

- 同一個設計理由只寫一次,寫在 `docs/`。
- 程式碼裡最多留一句「理由見 docs/某文件」。
- 不寫章節編號;要指到某一節時寫章節標題。

## 測試檔

放寬一條:「預期答案怎麼算出來」(手算過程)可以留在測試裡,用純文字寫。

- 理由:手算過程就是斷言的答案來源,跟斷言放在一起才看得出答案對不對。
- 其他規則照舊。歷史、辯論、除錯經過、校準經過一樣不寫。

## 範例

`fc_float_values` 的 docstring:

```
"""FC 佇列的浮點數值段:a = (1 - 1/tau) ** delta_t,b = w[:, 來源] * event_gain。

w: (n_out, n_in) 權重,w[i, j] 是 j -> i 的權重。
event_gain: (n_events,) 乘進權重的增益。接在上一層後面時傳上一層的 s_spike,
    理由見 docs/問題紀錄.md。None 等於全 1。
回傳 AffineMap,a、b 形狀 (n_out, n_events);pad 位置是 a=1、b=0。
"""
```

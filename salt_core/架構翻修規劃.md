## 1. 定案方向：按「抽象層級」切，不是按「conv / FC」切

一個網路 = 幾個 layer 排成一列，中間流動的是事件流（帶時間戳的 spike）。
問題出在共用錯了接縫：神經元邏輯共用是對的，但「跨層轉接」也被做成萬能的、什麼都懂的中間人——那才是不該通用的地方。

分四層：

### 第一層：神經元行為 + 跑一層的機制

一顆神經元的行為（漏電、累加、放電、重置）是一條固定公式，是模型的物理本身。
不管神經元在 conv 還是 FC，行為完全一樣；差別只在「哪些事件送到哪顆神經元、用什麼權重」，那是接線的事。

→ **維持一份共用的神經元模擬器**，它不知道也不需要知道 conv / FC。
→ 「哪些是填充事件」的資訊傳法**統一成一種形式**。

### 第二層：每種 layer 怎麼從輸入 + 權重算出自己的東西

conv 和 FC 在這裡做的事本質上不同，就讓它們不同，不硬湊成一套共用簽名。
它們只要在「吐出來的東西長什麼形狀」上一致——像 PyTorch 每個 layer 都同意「我吐一個 tensor」。

### 第三層：層跟層之間的接線

**不要萬能中間人。**
改成每個 layer 自己負責兩件事：看得懂標準輸入流、吐得出標準輸出流。
某個 layer 內部有什麼奇怪的記帳（壓縮版的索引查表），留在那個 layer 裡面自己清掉，吐出去給下一層之前就是乾淨的。

**唯一的跨層共用約定 = 一個標準事件流**：一串「什麼時候、哪顆神經元、多強」。

### 第四層：組一個網路

給一列 layer，把輸入流餵進去，一層層轉換，最後出結果。
以後要加 pooling / residual / 別的 layer 型別——照同一個標準寫一個新 layer，組裝邏輯不用動。
逐層超參（門檻、平滑係數、chunk 大小、init 尺度）變成**每個 layer 自己的設定**，不是巨型 config 裡的一堆純量。

### layer 的自我初始化（找 k、找 L）也是核心能力，不是應用端膠水

「這層的初始權重尺度該多少」「這層的壓縮佇列該多長」——這是 layer 自己該知道怎麼算的東西，核心提供。
應用端只該說「幫我做一個 conv layer、用這批資料初始化它」。

- **找 L（佇列長度）**：純幾何 primitive（`receptive_field_tap_count`）+「掃過整個資料集取 max」。
  4b 之後改成**動態找**（起始猜測 + 訓練中偵測出界 → 放大 → 退 checkpoint → 重編譯續練）。
- **找 k（初始尺度）**：「調整初始尺度直到某個 per-layer 診斷命中目標」的通用機制（bracket + bisection），
  收進 `salt_core/calibrate.py`。**介面讓「診斷 + 目標」可替換，不焊死 firing-rate。**

## 2. 輸出層：編碼方式是可替換的「解碼器」

SNN 輸出編碼不只一種：膜電位回歸、頻率編碼、群體編碼……以後還可能更多。
所以不能把「輸出 = 讀最終電壓」寫死。

把兩件事分開：

- **跑最後一層**：它就是一個普通 layer，沒有特殊型別。
- **把最後一層的活動解讀成預測**：獨立、可替換的「解碼器」。
  膜電位回歸 / 頻率 / 群體 = 三種解碼器。換編碼 = 換解碼器，網路其他部分不動。

「不 fire / 純積分」不是特殊型別，是**最後一層的門檻設定**，跟解碼器配套選。

### 怎麼紀錄

一分為二：

- **每一層都有的通用診斷**（spike 數、firing rate、兩個出界訊號）——所有 layer 統一產出一小份固定紀錄（`LayerDiag`）。
- **編碼特定的指標**——解碼器自己產出它那份。

訓練迴圈不寫死「loss = 交叉熵（最終電壓）」，而是向解碼器要「拿去算 loss 的東西」。

## 3. 已決定 / 還沒決定

### 已決定（全數落實）

- 四層切分（神經元模擬器共用 / 佇列建構各自 / 接線由 layer 自理 / 組裝器獨立）。
- 標準事件流（`EventStream` 四欄：`event_times` / `event_source_idx` / `event_gain` / `n_real_events`）是唯一的跨層共用約定；另加固定的 `LayerDiag`。
- 每個 layer 自足；逐層超參下放成 layer 欄位；通用組裝器 `run_network` / `build_network`。
- layer 的自我初始化（找 k、找 L）是核心能力：`salt_core/calibrate.py` + layer 方法。找 k 的「診斷 + 目標」可替換。
- 輸出編碼 = 可替換的解碼器（`salt_core/decoder.py` 三種）；最後一層是普通 layer；「不 fire」只是門檻設定。
- 「填充事件」資訊統一（`core.normalize_real_events`）。
- init_k 掃描要問的「哪些連接在幾何上合法」獨立成 `receptive_field_tap_count`，不借佇列建構器。
- 密集版 conv 佇列建構整個刪掉（4d）。

### 還沒決定

- 找 k 的**準則**（要不要 firing-rate、目標帶多少）——問題紀錄第十二節 / 盤點 §1.5，重新設計時再定。
  「能力放核心、`measure` 跟目標帶可注入」已做（`calibrate_init_scale` 完全準則無關，
  `ConvLayer.calibration_measure` 只是**預設**的 firing-rate measure，可換）。

### 2026-09-07 config / 參數規則整理（隨 step 4/5 一起收尾）

- **核心層類別帶預設值**：`ConvLayer` / `FCLayer` 的「很少調的旋鈕」（`tau=16` / `v_th` conv 1.0 fc 1e9 / `alpha=2.0` / `chunk_size=1` / `L=128` / `max_out_spikes=8192`）在 dataclass 欄位就有預設，必填只剩 `name` + 幾何。
- **網路定義變成 config**：`build_network(cfg)` 讀 `model.input_shape` + `model.layers` list，空間尺寸 / `ic` 串接 / FC `n_in` 全由 builder 推導；層名自動 `conv1`/`conv2`/`fc1`。`CONV1` / `CONV2` / `N_FC_IN` 常數、`_check_chain`、`_opt_init_k` 刪掉。
- **`ConvNetParams` NamedTuple 刪掉** → `init` 回「對齊 layer list 的位置 tuple」；`train_conv_compressed.py` 的 `params._fields` 三處改用位置 index / `layer.name`（解掉盤點 §4.6）。
- `build_decoder(cfg, layers)`，`n_fc_out` 讀 `layers[-1].n_out`；config 加 `model.decoder`（留白 = `membrane_regression`）。
- 邊界釐清：`salt_core` 規定「layer 怎麼設定、怎麼串」；config 檔的格式 / key 名 / 版本管理是開發者的事，library 不接管、entry 少 key 或多 key 就在 builder 直接炸。

### 2026-09-06 step 4 動手前拍板（已落實）

- **conv→conv 扁平編號還原**：放在 `ConvLayer.forward` 內，用該層自己的 `h_in`/`w_in` 靜態欄位；網路輸入在入口 ravel 一次，沒有第一層特例。
- **動態找 L\* 是 layer 核心能力**：`LayerDiag` 固定帶「每顆神經元真實 tap 數 max」+「真實輸出 spike 總數」；層提供 `grown_to_fit(diag) -> Layer`；「退 checkpoint + 重編譯」留訓練腳本但寫成對層 list 的通用迴圈。
- 密集版 `build_conv_queue` 刪掉不留當測試 oracle；壓縮版等價測試的 ground truth 改用 `_reference.py` 的透明參考實作。
